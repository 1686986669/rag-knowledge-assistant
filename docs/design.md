# 需求、接口和排障

用户故事：开发人员输入故障问题，获得可追溯的知识条目；维护人员更新文档并重建索引。
验收：首次导入可查；重复导入不重复；删文档后旧内容不可查；未知问题不伪造来源。

CLI：`ingest folder` 原子重建快照；`ask question [--live]` 返回 JSON。`--db path` 是全局选项，放在子命令前。
数据表：chunks(source, position, content)，复合主键 source/position。索引文件属于派生数据，不提交仓库。

故障定位：空结果先核对文档编码和切块，再检查问题与资料的词法交集；401 检查 Key，429 检查配额，网络失败检查代理与 HTTPS endpoint。不要在 issue 粘贴 Key 或私人资料。

安全边界：只导入自己确认的目录，跳过指向目录外的 Markdown 链接；导入文档不执行。模型提示明确把资料当作数据，但仅靠提示不能保证抵御所有 prompt injection。项目没有工具执行能力。

设计取舍：标准库实现以降低部署门槛；不是 LangChain/向量数据库项目。真实模型网络异常会报错，不静默伪造回答。
